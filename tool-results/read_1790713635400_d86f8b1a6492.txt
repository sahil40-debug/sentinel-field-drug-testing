     4→# Digital Companion for Field Drug Testing
     5→
     6→## 1. Product Overview
     7→
     8→### Project
     9→
    10→Digital Companion for Field Drug Testing
    11→
    12→### Problem Statement
    13→
    14→Smart India Hackathon 2026 — PS-231
    15→
    16→### Purpose
    17→
    18→The Digital Companion for Field Drug Testing is a software system designed to assist officers during presumptive field drug testing using existing colour-change testing kits.
    19→
    20→The system does not replace the physical testing kit or laboratory confirmation.
    21→
    22→Instead, it provides a digital workflow around the existing testing process:
    23→
    24→1. Select the substance/test being performed.
    25→2. Load the corresponding reference colour information.
    26→3. Capture or upload an image of the completed field test.
    27→4. Verify image quality.
    28→5. Detect the reference colour card.
    29→6. Detect the reaction/test area.
    30→7. Calibrate colour measurements using the reference card.
    31→8. Compare the reaction against the expected reference.
    32→9. Produce a Positive, Negative, or Inconclusive result.
    33→10. Store the complete test record.
    34→11. Generate a tamper-evident record using hashing.
    35→12. Allow later verification and review.
    36→
    37→The result is intended as a presumptive field-testing result and not as laboratory confirmation.
    38→
    39→---
    40→
    41→# 2. Goals
    42→
    43→## Primary Goals
    44→
    45→- Digitize the field drug-testing workflow.
    46→- Reduce dependence on manual visual interpretation.
    47→- Standardize colour analysis.
    48→- Account for lighting differences using a reference colour card.
    49→- Associate every analysis with the correct drug/test definition.
    50→- Produce deterministic and explainable classification.
    51→- Maintain a searchable digital history of tests.
    52→- Preserve evidence associated with each test.
    53→- Detect later modification of stored test records.
    54→- Provide a verification mechanism for stored records.
    55→
    56→## Secondary Goals
    57→
    58→- Provide a simple workflow for field officers.
    59→- Reduce manual record-keeping.
    60→- Provide supervisors with access to historical test results.
    61→- Make the system modular enough for additional tests and substances to be added later.
    62→
    63→---
    64→
    65→# 3. Non-Goals
    66→
    67→The system will NOT:
    68→
    69→- Replace laboratory confirmation.
    70→- Perform chemical identification directly.
    71→- Claim that image analysis alone can identify an unknown substance.
    72→- Automatically determine an unknown drug without a selected test definition.
    73→- Replace the physical field-testing kit.
    74→- Provide forensic-grade conclusions from a photograph alone.
    75→- Depend on cloud AI services for the core classification logic.
    76→- Require new physical hardware for the prototype.

   280→Attempt 1
   281→+
   282→Boundary evidence

   284→Attempt 2
   285→+
   286→Multi-region colour verification

   290→11. Reaction Area Detection
   291→
   292→The system identifies the reaction/test area separately from the reference card.
   293→
   294→The reaction area provides:
   295→
   296→Bounding box
   297→Detection confidence
   298→Colour uniformity
   299→Measured colour
   300→
   301→The reaction area must be successfully detected before classification.
   302→
   303→12. Colour Calibration
   304→
   305→The reference card is used to compensate for differences between:
   306→
   307→Expected reference colour
   308→Colour actually observed in the image
   309→
   310→The system calculates RGB correction factors.
   311→
   312→Conceptually:
   313→
   314→Expected Reference RGB
   315→        ↓
   316→Measured Reference RGB
   317→        ↓
   318→RGB Correction Factors
   319→        ↓
   320→Reaction RGB
   321→        ↓
   322→Calibrated Reaction RGB
   323→
   324→This allows the system to reduce the effect of lighting/camera differences.

   346→Negative

   353→Reaction confidence
   354→Reaction uniformity
   355→

   357→
   358→Positive RGB distance:
   359→45+
   360→
   361→Negative RGB distance:
   362→25 or below
   363→
   364→Positive hue tolerance:
   365→12
   366→
   367→Negative hue tolerance:
   368→8

   372→15. Classification Safety
   373→
   374→The system should return Inconclusive when:
   375→
   376→Reaction information is unavailable.
   377→Reference information is unavailable.
   378→Reaction detection confidence is too low.
   379→Reaction colour is insufficiently uniform.
   380→Colour measurements fall between positive and negative boundaries.
   381→
   382→The system must not force a binary answer when the available evidence is insufficient.
