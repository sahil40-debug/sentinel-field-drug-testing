     4→     4→# Digital Companion for Field Drug Testing
     5→     5→
     6→     6→## 1. Product Overview
     7→     7→
     8→     8→### Project
     9→     9→
    10→    10→Digital Companion for Field Drug Testing
    11→    11→
    12→    12→### Problem Statement
    13→    13→
    14→    14→Smart India Hackathon 2026 — PS-231
    15→    15→
    16→    16→### Purpose
    17→    17→
    18→    18→The Digital Companion for Field Drug Testing is a software system designed to assist officers during presumptive field drug testing using existing colour-change testing kits.
    19→    19→
    20→    20→The system does not replace the physical testing kit or laboratory confirmation.
    21→    21→
    22→    22→Instead, it provides a digital workflow around the existing testing process:
    23→    23→
    24→    24→1. Select the substance/test being performed.
    25→    25→2. Load the corresponding reference colour information.
    26→    26→3. Capture or upload an image of the completed field test.
    27→    27→4. Verify image quality.
    28→    28→5. Detect the reference colour card.
    29→    29→6. Detect the reaction/test area.
    30→    30→7. Calibrate colour measurements using the reference card.
    31→    31→8. Compare the reaction against the expected reference.
    32→    32→9. Produce a Positive, Negative, or Inconclusive result.
    33→    33→10. Store the complete test record.
    34→    34→11. Generate a tamper-evident record using hashing.
    35→    35→12. Allow later verification and review.
    36→    36→
    37→    37→The result is intended as a presumptive field-testing result and not as laboratory confirmation.
    38→    38→
    39→    39→---
    40→    40→
    41→    41→# 2. Goals
    42→    42→
    43→    43→## Primary Goals
    44→    44→
    45→    45→- Digitize the field drug-testing workflow.
    46→    46→- Reduce dependence on manual visual interpretation.
    47→    47→- Standardize colour analysis.
    48→    48→- Account for lighting differences using a reference colour card.
    49→    49→- Associate every analysis with the correct drug/test definition.
    50→    50→- Produce deterministic and explainable classification.
    51→    51→- Maintain a searchable digital history of tests.
    52→    52→- Preserve evidence associated with each test.
    53→    53→- Detect later modification of stored test records.
    54→    54→- Provide a verification mechanism for stored records.
    55→    55→
    56→    56→## Secondary Goals
    57→    57→
    58→    58→- Provide a simple workflow for field officers.
    59→    59→- Reduce manual record-keeping.
    60→    60→- Provide supervisors with access to historical test results.
    61→    61→- Make the system modular enough for additional tests and substances to be added later.
    62→    62→
    63→    63→---
    64→    64→
    65→    65→# 3. Non-Goals
    66→    66→
    67→    67→The system will NOT:
    68→    68→
    69→    69→- Replace laboratory confirmation.
    70→    70→- Perform chemical identification directly.
    71→    71→- Claim that image analysis alone can identify an unknown substance.
    72→    72→- Automatically determine an unknown drug without a selected test definition.
    73→    73→- Replace the physical field-testing kit.
    74→    74→- Provide forensic-grade conclusions from a photograph alone.
    75→    75→- Depend on cloud AI services for the core classification logic.
    76→    76→- Require new physical hardware for the prototype.
    77→    77→

   154→   154→
   155→   155→For the current prototype, the database is stored as JSON.
   156→   156→
   157→   157→Each test definition contains information such as:
   158→   158→
   159→   159→Test ID
   160→   160→Drug/substance name
   161→   161→Alternative/common names
   162→   162→Test name
   163→   163→Test category
   164→   164→Reference colour
   165→   165→Reference shade
   166→   166→Reference colour HEX value
   167→   167→Expected reaction information
   168→   168→Detection notes
   169→   169→Classification configuration
   170→   170→Status
   171→   171→
   172→   172→Example:
   173→   173→
   174→   174→{
   175→   175→  "test_id": "TEST-001",
   176→   176→  "substance": "Example Substance",
   177→   177→  "test_name": "Example Colour Test",
   178→   178→  "category": "Field Presumptive Test",
   179→   179→  "reference_colour": {
   180→   180→    "group": "Yellow",
   181→   181→    "shade": "Shade 1",
   182→   182→    "hex": "#F0DC78"

   255→   255→10. Reference Card Detection
   256→   256→
   257→   257→The physical test image contains a reference colour card.
   258→   258→
   259→   259→The system detects the reference card using:
   260→   260→
   261→   261→Colour similarity
   262→   262→Shape
   263→   263→Size
   264→   264→Rectangularity
   265→   265→Colour consistency
   266→   266→Boundary evidence
   267→   267→Multi-region verification
   268→   268→
   269→   269→The current implementation uses a three-stage verification process.
   270→   270→
   271→   271→Attempt 1
   272→   272→Colour
   273→   273→+
   274→   274→Shape
   275→   275→+
   276→   276→Size
   277→   277→+
   278→   278→Colour consistency
   279→   279→Attempt 2
   280→   280→Attempt 1
   281→   281→+
   282→   282→Boundary evidence
   283→   283→Attempt 3
   284→   284→Attempt 2
   285→   285→+
   286→   286→Multi-region colour verification
   287→   287→
   288→   288→Only a sufficiently verified reference card is accepted.
   289→   289→
   290→   290→11. Reaction Area Detection
   291→   291→
   292→   292→The system identifies the reaction/test area separately from the reference card.
   293→   293→
   294→   294→The reaction area provides:
   295→   295→
   296→   296→Bounding box
   297→   297→Detection confidence
   298→   298→Colour uniformity
   299→   299→Measured colour
   300→   300→
   301→   301→The reaction area must be successfully detected before classification.
   302→   302→
   303→   303→12. Colour Calibration
   304→   304→
   305→   305→The reference card is used to compensate for differences between:
   306→   306→
   307→   307→Expected reference colour
   308→   308→Colour actually observed in the image
   309→   309→
   310→   310→The system calculates RGB correction factors.
   311→   311→
   312→   312→Conceptually:
   313→   313→
   314→   314→Expected Reference RGB
   315→   315→        ↓
   316→   316→Measured Reference RGB
   317→   317→        ↓
   318→   318→RGB Correction Factors
   319→   319→        ↓
   320→   320→Reaction RGB
   321→   321→        ↓
   322→   322→Calibrated Reaction RGB
   323→   323→
   324→   324→This allows the system to reduce the effect of lighting/camera differences.
   325→   325→
   326→   326→13. Colour Analysis
   327→   327→
   328→   328→The current prototype measures:
   329→   329→
   330→   330→Original RGB
   331→   331→Original HSV
   332→   332→Reference RGB
   333→   333→Reference HSV
   334→   334→RGB distance
   335→   335→Calibrated RGB
   336→   336→Calibrated HSV
   337→   337→Calibrated RGB distance
   338→   338→
   339→   339→The system uses the calibrated values for classification.
   340→   340→
   341→   341→14. Classification
   342→   342→
   343→   343→The current classification engine produces:
   344→   344→
   345→   345→Positive
   346→   346→Negative
   347→   347→Inconclusive
   348→   348→
   349→   349→The classifier uses deterministic rules based on:
   350→   350→
   351→   351→Calibrated RGB distance
   352→   352→Hue difference
   353→   353→Reaction confidence
   354→   354→Reaction uniformity
   355→   355→
   356→   356→Current prototype thresholds:
   357→   357→
   358→   358→Positive RGB distance:
   359→   359→45+
   360→   360→
   361→   361→Negative RGB distance:
   362→   362→25 or below
   363→   363→
   364→   364→Positive hue tolerance:
   365→   365→12
   366→   366→
   367→   367→Negative hue tolerance:
   368→   368→8
   369→   369→
   370→   370→These values are prototype thresholds and must be validated against appropriate test samples before real-world deployment.
   371→   371→
   372→   372→15. Classification Safety
   373→   373→
   374→   374→The system should return Inconclusive when:
   375→   375→
   376→   376→Reaction information is unavailable.
   377→   377→Reference information is unavailable.
   378→   378→Reaction detection confidence is too low.
   379→   379→Reaction colour is insufficiently uniform.
   380→   380→Colour measurements fall between positive and negative boundaries.
   381→   381→
   382→   382→The system must not force a binary answer when the available evidence is insufficient.

   714→   714→Modular
   715→   715→
   716→   716→Each major operation is isolated.
   717→   717→
   718→   718→Backward Compatible
   719→   719→

   721→   721→
   722→   722→Deterministic
   723→   723→
   724→   724→The current classification engine uses explicit rules rather than an opaque AI model.
   725→   725→
   726→   726→Explainable
   727→   727→
   728→   728→The system should preserve the measurements that produced the result.
   729→   729→
   730→   730→Testable
   731→   731→

   733→   733→
   734→   734→Evidence-Oriented
   735→   735→
   736→   736→The final record should retain enough information for later review and integrity verification.
